**#4 — stale 판정 기준이 틀려 있었습니다.**
`connected_at`(연결 시각)으로 동기화 정체를 판정하고 있었습니다. 실제 동기화
시작 시각을 기록하는 `sync_started_at` 컬럼을 추가하고, 스키마·런타임 ALTER·

런타임 ALTER 는 멱등이라 기존 DB 도 재시작만으로 반영됩니다.

**#6 — `failed` 문서를 사용자가 지울 수 없었습니다.**

## 4. 프론트엔드 영향

**파일 변경 0건입니다.** 다만 **관찰 가능한 API 동작 변화가 있습니다.**

`upload_document()` 의 검사 순서가 바뀌었습니다.

```
(미들웨어)           401   ← JWT 미인증. 진입 전 처리, 이 변경과 무관
filename 검증        400
확장자 검증          400
require_upload_user()          ← 사용자 확인 실패 시 503
require_project_access()       ← 비구성원이면 403
await file.read()
크기 검사            413
```

| 상황 | 이전 | 이후 |
|---|---|---|
| 인증된 비구성원 + 대용량 | 413 | **403** |
| 사용자 확인 실패 + 대용량 | 413 | **503** (`UPLOAD_USER_REQUIRED`) |
| 정상 구성원 + 대용량 | 413 | 413 (유지) |
| JWT 미인증 + 대용량 | 401 | 401 (변화 없음) |

**정상 구성원 경로의 계약(10MB 초과 → 413)은 유지됩니다.**
프론트가 413 만 특별 처리하고 403·503 을 일반 오류로 다룬다면 사용자에게 보이는
메시지가 달라집니다.

## 6. 잔여 리스크

**F-012 의 범위 한계** — 2절 #3 참조. 네트워크 수신·스풀은 여전히 일어납니다.

**타임존** — 실제 MySQL 테스트에서 Python `datetime.now()`(호스트 KST)와
컨테이너 `NOW()`(UTC)가 어긋나 "3시간 전"이 미래로 보였습니다. DB 쪽 연산
(`NOW() - INTERVAL`)으로 해결했으나, 앞으로 추가되는 시각 비교 테스트도 같은
함정에 빠질 수 있습니다.

**검증의 성격** — 독립 검증자가 읽기 전용 샌드박스에서 `uv` 캐시 쓰기와 Docker
소켓 접근이 막혀 테스트 게이트를 **직접 재실행하지 못했습니다.** 게이트는 사용자가
실행한 로그로 판정했고, 검증자는 이를 **보조 증거**로 명시했습니다. 저장소 수준
문제로 별도 태스크로 분리했습니다.
