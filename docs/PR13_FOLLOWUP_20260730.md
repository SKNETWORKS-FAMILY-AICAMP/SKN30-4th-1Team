## 2. 결론과 권고 결정

PR #21에는 PR #13의 핵심인 **현재 데스크톱 채팅의 local-only 계약**이 보존되어 있다. 빠진 것은 서버 유출 방지 자체가 아니라 다음 항목이다.

1. 대화·초안의 로컬 저장 실패를 사용자에게 알리는 안전장치
2. 첨부만 변경된 초안의 즉시 영속화
3. local-only 관련 영문 번역
4. 현재 구조와 어긋난 아키텍처 문서 정리
5. 실제 무저장·재시작 복원·저장 실패 회귀 테스트

권고 결정은 다음과 같다.

- 위 누락을 PR #21 후속 브랜치에 반영한 뒤 PR #13을 `#21로 대체됨`으로 닫는다.
- 일정상 PR #13을 먼저 닫아야 한다면 “모든 변경이 완전히 포함됐다”고 쓰지 않는다.
- 먼저 닫을 경우, 이 문서를 후속 작업의 단일 체크리스트로 연결하고 아래 종료 승인 기준을 그대로 적용한다.

## 3. 보존된 local-only 계약

### 3.1 현재 데스크톱 동작

PR #21의 현재 데스크톱은 다음 구조를 사용한다.

- `d75f560:desktop/src/App.tsx:4295-4320`
  - 최근 대화와 현재 질문을 `POST /api/v1/projects/{project_id}/query`로 보낸다.
  - 데스크톱에서 서버 세션 생성·수정·삭제 API를 호출하지 않는다.
- `d75f560:desktop/src/App.tsx:843-879`
  - 이전 로컬 데이터에 남아 있는 `serverSessionId`를 로드 시 제거한다.
- `d75f560:desktop/src/types.ts:50-55`
  - 현재 `ChatSession` 모델에 서버 세션 ID가 없다.
- `d75f560:backend/api/capabilities.py:27-31`
  - 서버 capability는 `storage: local_only`, `server_persistence: false`, `legacy_session_api: deprecated`를 선언한다.
- `d75f560:backend/api/query.py:124-164`
  - `/query`는 받은 질문과 history를 답변 생성에 전달하지만 chat table에 직접 쓰지 않는다.

### 3.2 계약의 정확한 의미

local-only의 의미는 아래와 같이 한정한다.

> 현재 데스크톱이 사용하는 `/query` 흐름은 채팅방 제목, 질문, 답변, 초안을 `chat_sessions`, `chat_messages`, `chat_summaries`에 저장하지 않는다.

다음은 이 계약에 포함되지 않는다.

- 질문과 최근 history는 답변 생성을 위해 PaiM 백엔드로 전송된다.
- 설정된 외부 LLM 제공자에도 답변 생성에 필요한 내용이 전달될 수 있다.
- deprecated인 `/api/v1/projects/{project_id}/sessions/*`는 아직 동작한다.
- 구형 클라이언트가 deprecated 세션 API를 호출하면 서버에 암호화된 세션 데이터를 저장한다.
- 기존 서버 세션 데이터는 별도 마이그레이션 전까지 남아 있다.

따라서 “서버 DB에 채팅을 저장하지 않는다”와 “서버 또는 외부 LLM에 채팅을 전혀 보내지 않는다”를 같은 뜻으로 설명하면 안 된다.

### 3.3 레거시 API 상태

`d75f560:backend/chat/router.py:122-220,392-402`의 세션 API는 OpenAPI에서 deprecated로 표시되지만 삭제되거나 차단되지는 않았다. `backend/chat/session_store.py`도 레거시 세션 메시지·요약 저장을 위해 유지된다.

이 상태는 롤백·구형 클라이언트 호환 목적으로 수용할 수 있다. 단, 모든 현재형 문서에서 “새 데스크톱의 기본 저장 경로”처럼 설명해서는 안 된다.

## 4. 누락 1: 대화 저장 실패

### 4.1 PR #13 동작

`a8e8847:desktop/src/App.tsx:3205-3219`는 프로젝트·세션·대화 상태를 localStorage에 저장할 때 예외를 잡고 다음 경고를 표시한다.

> 로컬 저장 공간이 부족해 최신 대화를 저장하지 못했습니다

### 4.2 PR #21 현재 동작

`d75f560:desktop/src/App.tsx:3401-3406`은 `window.localStorage.setItem()`을 try/catch 없이 React effect에서 호출한다.

저장 공간 한도 초과, WebView 저장소 오류 또는 저장소 접근 제한으로 `setItem()`이 실패하면 다음 문제가 생길 수 있다.

- 최신 질문과 답변은 현재 화면의 React 메모리에는 보여도 디스크에는 남지 않는다.
- 앱을 다시 열면 마지막으로 성공한 저장본으로 되돌아가 최신 대화가 사라진다.
- 현재 채팅은 서버에도 백업되지 않으므로 다른 복구 경로가 없다.
- 예외가 effect 밖으로 전파된다.
- `desktop/src/main.tsx`에 ErrorBoundary가 없어 앱 루트가 내려가거나 빈 화면이 될 가능성이 있다.

마지막 항목은 정적 코드에서 확인한 위험이다. 설치본별 WebView 동작까지 실행 검증된 사실로 과장하지 않는다.

### 4.3 용량 증가 특성

`d75f560:desktop/src/App.tsx:1509-1533`은 모든 로컬 세션의 전체 메시지 본문을 프로젝트 상태에 저장한다. 서버에 전달하는 history는 `QUERY_HISTORY_LIMIT = 20`으로 제한되지만 로컬 저장 메시지 수는 같은 방식으로 잘리지 않는다.

이미지 `previewUrl`은 저장 전에 제거되므로 큰 data URL 증가는 완화된다. 그러나 긴 대화와 많은 세션이 누적되면 localStorage 한도에 도달할 가능성은 계속 존재한다.

## 5. 누락 2: 초안 저장 실패

### 5.1 PR #13 동작

`a8e8847:desktop/src/App.tsx:1419-1436`의 `saveSessionDrafts()`는 성공 여부를 반환한다. `a8e8847:desktop/src/App.tsx:6808-6819`의 `persistSessionDrafts()`는 실패 시 다음 경고를 표시한다.

> 로컬 저장 공간이 부족해 최신 초안을 저장하지 못했습니다

### 5.2 PR #21 현재 동작

`d75f560:desktop/src/App.tsx:1492-1507`은 초안 저장 예외를 catch한 뒤 무시한다. `d75f560:desktop/src/App.tsx:7195-7253`의 모든 호출부도 성공 여부를 확인하지 않는다.

사용자 영향은 다음과 같다.

- 입력창과 메모리 Map에는 초안이 남아 저장된 것처럼 보인다.
- 같은 앱 실행 중 세션을 오갈 때는 초안이 보일 수 있다.
- 앱 재시작·충돌·업데이트 뒤에는 마지막 저장 성공 이후의 초안이 사라진다.
- 사용자에게 실패 사실이 표시되지 않는다.

local-only 설계에서는 서버 백업이 없으므로 이 문제를 단순 알림 품질 문제로 분류하지 않는다. 사용자가 복사하거나 다른 곳에 보관할 기회를 주는 데이터 유실 경고다.

## 6. 누락 3: 첨부-only 초안 회귀

PR #13은 `a8e8847:desktop/src/App.tsx:3221-3236`에서 `prompt`와 `attachments` 변경을 함께 감시해 초안을 자동 저장했다.

PR #21은 이 effect를 제거하고 주로 텍스트 입력 시점에 초안을 저장한다.

- 첨부 추가: `d75f560:desktop/src/App.tsx:7317-7358`
- 첨부 제거: `d75f560:desktop/src/App.tsx:7438-7442`
- 텍스트 입력 시 저장: `d75f560:desktop/src/App.tsx:7183-7204`

첨부를 추가하거나 제거한 뒤 텍스트를 더 입력하지 않고 앱을 닫으면 첨부 변경이 draft storage에 반영되지 않을 수 있다. 화면을 이동할 때 `rememberCurrentDraft()`가 호출되는 경로는 있지만, 앱 종료·충돌을 대신 보장하지 않는다.

후속 구현은 프로젝트 상세 composer와 기존 채팅 composer 모두에서 아래 변경을 저장해야 한다.

- 텍스트 입력
- 첨부 추가
- 첨부 제거
- 초안 비우기
- 세션·프로젝트 전환

## 9. 테스트 사각지대

### 9.1 백엔드 무저장 계약

PR #13의 `a8e8847:tests/test_local_chat_policy.py:38-65`에는 실제 `/query` 요청에서 실행된 SQL을 기록하고 `chat_*` SQL이 없음을 확인하는 `test_stateless_query_does_not_write_server_chat_tables`가 있었다.

PR #21의 `d75f560:tests/test_local_chat_policy.py:10-45`는 다음을 확인한다.

- capability 선언
- 세션 API deprecated 표시
- OpenAPI의 `x-paim-chat-persistence: none`
- `App.tsx`에 `"/sessions"` 문자열이 없음
- draft helper 문자열 존재

이 검사는 선언과 소스 문자열을 확인하지만 다음 회귀는 잡지 못한다.

- OpenAPI 메타데이터는 그대로인데 `/query` 내부가 chat table을 쓰기 시작하는 경우
- 세션 API 호출이 다른 프런트 모듈이나 계산된 경로로 이동하는 경우
- localStorage 저장 함수가 존재하지만 실패를 숨기는 경우

### 9.2 프런트 재시작 복원

- `verifyLocalChatReloadAndFollowup`
- `verifyLocalDraftReload`

이 검사는 대화·초안 재시작 복원, 복원된 history의 후속 질문 전달, 서버 세션 API 무호출을 확인했다.

## 10. 의도적으로 제외 가능한 항목

다음은 PR #13 종료를 막지 않는 명시적 후속 범위로 둘 수 있다.

- WebView localStorage에서 앱 전용 암호화 저장소로 이전
- 암호화 키를 운영체제 보안 저장소에 보관
- 전체 로컬 대화 삭제 기능
- 선택적 대화 내보내기
- 기존 서버 세션 데이터 삭제 마이그레이션
- deprecated 세션 API의 완전 제거

단, 다음 조건이 필요하다.

- `docs/CHAT_STORAGE_POLICY.md`에 현재 한계와 후속 범위가 명시되어 있어야 한다.
- 새 데스크톱은 deprecated 세션 API를 호출하지 않아야 한다.
- deprecated API가 남아 있다는 사실을 아키텍처·API 문서에서 숨기지 않아야 한다.
- 보안 저장소 이전 전까지 localStorage 저장 실패를 사용자에게 알려야 한다.

다음은 의도적 제외로 권고하지 않는다.

- 대화 저장 실패 예외를 처리하지 않는 상태
- 초안 저장 실패를 조용히 무시하는 상태
- 첨부-only 초안이 종료 시 유실되는 상태
- 영어 모드에서 한국어 삭제·저장 실패 문구가 나오는 상태
- 현재 기본 구조를 서버 암호화 세션으로 설명하는 문서 모순
