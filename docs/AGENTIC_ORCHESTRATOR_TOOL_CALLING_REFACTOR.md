# 오케스트레이터 중심 동적 Tool Calling 변경안

## 현재 구조

```text
질문
→ 별도 QuestionScope LLM이 의도와 조건 분석
→ 오케스트레이터가 다시 질문을 보고 Tool 선택
→ Tool 호출을 QuestionScope와 비교·검증
→ Tool 실행
→ 필요하면 서버가 정해진 fallback Tool 실행
→ 답변 생성
```

- 질문 의도를 `QuestionScope LLM`과 오케스트레이터가 각각 판단한다.
- 두 판단이 다르면 정상적인 Tool 호출도 거부될 수 있다.
- 일부 상황에서는 서버가 오케스트레이터 대신 fallback Tool을 선택한다.

## 변경할 구조

```text
질문
→ 오케스트레이터가 의도와 조건 분석
→ 필요한 Tool 선택·호출
→ 서버가 호출 인자 검증 후 Tool 실행
→ 실행 결과를 오케스트레이터에게 반환
→ 추가 Tool 호출 또는 최종 답변 결정
```

- 의도 분석과 Tool 선택의 주체를 오케스트레이터 하나로 통합한다.
- Tool 종류와 호출 순서를 미리 고정하지 않는다.
- SQL 결과를 확인한 뒤 RAG Tool을 호출하는 등 결과에 따라 다음 Tool을 동적으로 선택한다.
- 서버는 Tool을 대신 선택하지 않고 스키마, 권한, 인자와 질문 조건의 유효성만 검증한다.
- 검증 실패는 오케스트레이터에게 반환하여 제한된 횟수 안에서 다시 판단하게 한다.
- 무한 반복을 막기 위한 최대 호출 횟수와 안전성 검증은 유지한다.

## 핵심 변경점

별도의 `QuestionScope LLM`과 서버 주도 fallback을 제거하고, 단일 오케스트레이터가 Tool 실행 결과를 보면서 다음 행동을 계속 판단하는 동적 Tool Calling 구조로 변경한다.
