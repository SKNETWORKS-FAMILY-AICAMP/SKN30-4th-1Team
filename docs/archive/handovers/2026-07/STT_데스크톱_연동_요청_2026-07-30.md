## 회의 녹음 STT 데스크톱 연동 요청

> 보관 상태: PR #27에서 데스크톱 구현 완료, `main` `dd7dda9`에 포함됨.
> 이 문서는 구현 당시 전달 계약을 보존하며 현재 API 정본은 `docs/API_명세서.md`다.

  ### 작업 기준

  - 데스크톱 기준: PR #20 최종 ecc4b10에서 생성한 프론트 후속 브랜치
  - 백엔드 API 참조: integration/pr18-stabilized-20260729 (d75f560)
  - 백엔드 브랜치를 데스크톱 작업 기준으로 사용하지 않는다.

  ### 목표

  데스크톱 프로젝트 자료함에서 회의 녹음을 업로드하고, CLOVA 전사 및 Project Memory 적재 상태를 보여준다.

  ### 업로드 진입점

  - 기존 일반 문서 업로드와 별도로 회의 녹음 업로드 진입점을 추가한다.
  - 오디오 파일은 한 번에 하나씩 업로드한다.
  - 기존 일반 문서 업로드 로직은 변경하지 않는다.

  지원 확장자:

  mp3
  mp4
  m4a
  wav
  aac
  ac3
  ogg
  flac

  wma는 지원하지 않는다.

  ### 회의 날짜

  오디오 선택 후 실제 회의 날짜를 확인한다.

  - 기본값: 오늘
  - 사용자가 수정 가능
  - 파일 수정일을 회의 날짜로 자동 사용하지 않음
  - 전송 형식: YYYY-MM-DD

  이 날짜는 “다음 주까지”, “내일까지” 같은 상대 마감일 추출의 기준일로 사용된다.

  ### 업로드 API

  POST /api/v1/projects/{project_id}/audio
  Content-Type: multipart/form-data

  FormData:

  file: 오디오 파일
  date: YYYY-MM-DD

  응답:

  {
    "doc_id": 71,
    "status": "processing",
    "provider": "clova",
    "diarization": true
  }

  응답의 doc_id를 기존 Attachment에 연결한다.

  ### 상태 확인

  기존 문서 상태 API를 재사용한다.

  GET /api/v1/projects/{project_id}/documents/{doc_id}/status

  - processing: 폴링 유지
  - indexed: 프로젝트 메모리와 문서 목록 새로고침
  - failed: last_error를 사용자에게 표시
  - 앱 재실행 시 문서 목록의 doc_type="meeting"을 오디오 자료로 처리

  CLOVA 전사와 후속 LLM 추출에는 시간이 걸릴 수 있으므로:

  - 오디오 폴링 최대 시간은 약 15분
  - 5~10초 간격 또는 점진적 backoff 권장
  - 시간이 초과되면 실패로 처리하지 않고 처리 지연으로 표시
  - 사용자가 수동으로 상태를 새로고침할 수 있게 한다.

  ### 취소 및 삭제

  DELETE /api/v1/projects/{project_id}/documents/{doc_id}

  기존 문서 업로드의 보상 삭제 방식을 재사용한다.

  서버가 doc_id를 생성한 뒤 로컬에서 취소된 경우, 해당 doc_id로 DELETE를 호출한다.

  ### 파일 크기

  백엔드는 CLOVA 오디오를 최대 200MB까지 허용하지만, 현재 Tauri는 파일 전체를 Base64로 읽는다.

  따라서 데스크톱은 임시로 파일당 25MB까지만 허용한다.

  - 일반 문서의 project_documents.max_file_bytes를 오디오 제한으로 재사용하지 않는다.
  - 오디오 전용 크기 검증 함수를 만든다.
  - 서버 제한과 데스크톱 임시 제한을 구분한다.
  - 200MB 지원은 스트리밍 업로드 도입 후 후속 처리한다.

  ### 드래그앤드롭

  프로젝트 자료함 드롭 경로도 오디오를 구분해야 한다.

  - 일반 문서: 기존 /documents 경로
  - CLOVA 지원 오디오 한 개: 회의 날짜 확인 후 /audio
  - 여러 오디오 동시 드롭: 업로드하지 않고 한 개씩 올리도록 안내
  - 폴더 내부 오디오: 이번 범위에서는 자동 STT 업로드하지 않음
  - 파일 선택과 드래그앤드롭은 동일한 오디오 업로드 함수를 사용

  ### 세션 대화 첨부

  세션 대화 입력창에서는 오디오를 받지 않는다.

  - 오디오를 첨부하거나 STT로 자동 전환하지 않는다.
  - 날짜 확인창도 열지 않는다.
  - 로컬 첨부 칩으로 남기지 않는다.
  - 다음 안내를 표시한다.

  음성 파일은 프로젝트 자료함의 회의 녹음 업로드를 이용해 주세요.

  ### 제외 범위

  - STT 제공자 선택 UI
  - 데스크톱 녹음 기능
  - 전사문 조회·편집 UI
  - 화자 라벨 표시·편집 UI
  - 화자 실명 추정
  - 여러 오디오 일괄 업로드
  - 200MB 스트리밍 업로드

  CLOVA의 익명 화자 정보는 백엔드가 내부 전사문에 보존하지만, 현재 API는 전사문을 프론트에 반환하지 않으므로 화자 UI는 만들지 않는다.

  ### 필수 테스트

  - 오디오는 /audio로 전송되고 /documents로 전송되지 않음
  - file, date가 FormData에 포함됨
  - 날짜 기본값이 오늘이며 수정 가능
  - processing → indexed
  - processing → failed 및 last_error 표시
  - 처리 지연 후 수동 새로고침
  - 업로드 취소 후 서버 문서 삭제
  - 프로젝트 자료함 오디오 드롭 분기
  - 세션 대화의 오디오 선택·드롭 거부
  - 여러 오디오 및 폴더 내부 오디오 제외
  - 일반 문서 업로드 회귀 없음
  - 데스크톱 build 및 layout/workspace 테스트 통과
